# WeaveTP 代码与设备说明

## 代码解决什么问题

同一个 MoE 模型从 TP2 切到 TP4、或从 TP4 切回 TP2 时，目标布局需要得到正确的参数分片和当前请求的有效 KV。WeaveTP 的工作是组织这次状态准备与接管，并降低特定配置下的重配置开销。

为什么切换 TP，由任务需求和剩余工作量决定；切换时搬什么，由目标实际持有的有效状态决定。当前测量原型预先安排切换，不包含完整的任务调度器或自动 TP 决策器。

## 主要模块怎么看

| 模块名称 | 职责 | 阅读时关注什么 |
|---|---|---|
| live MoE benchmark | 构造常驻 TP2/TP4 模型、推进 token、安排切换、记录指标 | 一次 launch 包含哪些工作，计时从哪里开始和结束 |
| refit / planning API | 建立和缓存状态重分片计划 | 逻辑参数、目标布局与计划之间的关系 |
| planner | 匹配张量身份与切片，建立源—目标复制任务 | 复制参数、partition stride、全局专家身份、逻辑 rank 映射 |
| bandwidth model / source selection | 使用带宽画像估计传输成本，筛选合法的等价源 | 等价源必须满足同一逻辑张量及分片/专家归属，不是任意 GPU 互换 |
| residual tracker / wave scheduler | 分批组织迁移任务 | 每波任务上限、方向差异及剩余任务；不是自动任务调度器 |
| async execution | 提交迁移、等待完成、提交目标写入 | launch / wait / commit 的生命周期及写入可见性 |
| copy services | 执行本地复制或远程传输 | 生产 GPU 数据通路为 NCCL；Gloo 的协调/CPU 通路应区分 |
| KV context / delta handling | 记录快照，搬运稳定前缀与追加区间，更新目标 offset | [0,s) 与 [s,c) 的覆盖，以及 handoff 前的就绪条件 |
| statistics / validation | 汇总实验和检查切换后输出 | 数值检查不等于逐 token 或所有状态完全等价 |

库中存在的更广泛并行布局支持，不等于已经在本项目的真实模型实验中全部验证。

## 一次运行在做什么

1. 准备兼容的 DeepSeek-V2-Lite checkpoint、模型配置与对应设备的带宽画像。
2. 建立 8 个 worker、通信组以及常驻的 TP2 和 TP4 布局，完成初始化和方向计划缓存。
3. 源端解码到快照边界 s，确定稳定 KV 前缀 [0,s)。
4. 使用缓存计划分波准备目标参数与稳定 KV；源端在允许的重叠窗口继续解码。
5. 源端到边界 c 停止推进，有限暂停期间补齐追加 KV [s,c)。
6. 等待必要写入完成并可见，提交状态、切换活跃布局、继续执行；benchmark 随后进行数值检查。
7. 一次 launch 执行 TP2→TP4→TP2→TP4→TP2，先在 launch 内汇总，再跨独立 launch 统计。

两个布局和通信组常驻，不是临时加入新 GPU、销毁 worker 或实际释放一组设备。正式实验的 online replanning、guard、packing 关闭，不能把它们当作已测收益来源。

## 在什么设备上运行过

| 用途 | 设备/系统 | 已确认范围 |
|---|---|---|
| 正式三轮与历史五轮 GPU benchmark | 8 × NVIDIA RTX 5090；DeepSeek-V2-Lite；TP2↔TP4；EP=2；64 专家；fixed-hot 路由 | 有原始 GPU 实验 JSON；不是 4 卡或 CPU 模拟结果 |
| 后续服务器环境只读确认 | 8 × RTX 5090，单卡约 32 GB；Ubuntu 22.04.5；Python 3.12.13；PyTorch 2.11.0+cu128；CUDA 12.8 | 属于后续检查时的环境，不是对正式实验软件版本的回溯锁定 |
| 本地开发与独立参考验证 | Windows、CPU | 小型张量参考、映射/接口测试和数据复算；不能代替真实 GPU 异步验证 |
| HarMoEny 原论文参考环境 | 8 × V100 DGX-1；官方 NVIDIA PyTorch 24.12 容器路线 | 是对方 artifact 的目标环境，不是本项目已有原生复现实验设备 |

真实模型 checkpoint 和带宽 profile 曾在后续服务器只读核对中确认存在；本资料包不包含大模型，也不代表当前服务器资源仍可直接使用。GPU 数量、空闲情况与使用额度要在再次运行前确认。

## 版本与验证范围

- newtext 是代码和实验的只读归档，不应当作日常开发目录。
- 本地快照不能直接认定为历史服务器运行的精确 Git 版本；现有开发工作副本还包含后续局部正确性修补。
- 正式性能数据、历史代理数据、后续正确性测试是不同批次，不互相替代。
- 后续强正确性工作已有 CPU 参考与测试设施；真实 GPU 通信、异步源读取、真实 EP 布局、真实模型状态与继续执行对照仍需相应运行证据。
- 当前接口对任务身份、有效 KV 区间和安全复用的保证不能仅由 shape、offset 或地址推断。

开始性能优化前，应先把当前开发版本、正确性验证版本和性能测量版本对齐，并补齐环境记录。
