## 基本信息

## 预估耗时
以下是按经验值估算，均未实测：

| 项目 | 估算值 |
|---|---|
| 27 层建模 + 初始同步 | 1–2 min |
| 单次 27 层规划 | 5–15 s |
| 单次 27 层迁移 | 3–4 s（约 6 个 wave，每个 wave 至少一个 0.32 s 的 decode 步） |
| 画像 | 约 5 s |
| 10 步 TPOT 基线 | 约 4 s |

smoke 会打印实测的 `setup_s`、`plan_build_s`、`switch_wall_ms`，跑完后可以用下面的公式重算：
- 行 b ≈ setup + 2·规划 + 4 ×（画像 + 基线 + 2·规划 + 16·迁移）+ 画像
- 行 c ≈ setup + 2·规划 + 画像 + 基线 + 8·规划 + 40·迁移 + 画像

| 步骤 | 预估 |
|---|---|
| CPU 回归 | 1–2 min |
| smoke | 4–6 min |
| 行 a（n=3/7/14/27，共 4 次启动） | 8–12 min |
| 行 b | 7–10 min |
| 行 c | 5–8 min |

如果 smoke 实测后行 b 或行 c 预计超过 6 分钟，用 `REPEATS=2 bash …` 把计时次数降到 2。

## 3. smoke（可以和别人同卡运行）
```bash
bash "$ABL/run_smoke.sh"
```

逐项核对 `$ROOT/smoke/run.log` 的输出：
- `[smoke] L1..L4 validation_max_diff=… plan_build_s=… transfer_ms=… switch_wall_ms=… network=… local=… pad=…`：四个级别都打印，没有 `AssertionError`；L1/L2 的网络字节、本地拷贝字节、补字节数也在这一行；
- `[smoke] validation passed for [...] and for L2 under flood 0:24,1:24`：开灌流后的那次校验也通过；
- `[memory] after build`、`during L1 migration`、`end`：每张卡的峰值显存（allocated/reserved GiB）。GPU4/5 上还有别人约 4.4 GB，要留出余量；
- `[smoke] decode step ms: idle=… flood=…`，以及两种条件下的带宽差；
- `[smoke] L2 cross-socket share of network bytes=…`；
- `[smoke] flood 0:24,1:24: transfer L3/L2=…, m=1 L4/L3=…`；
- `[plan] … build_s=…` 和 `[launch] … setup_s=…`：用来重算上面的预估耗时。

## 4. 三行（正式行要求连续 10 s 内所有 GPU 利用率为 0%）
```bash
bash "$ABL/run_row_a.sh"
bash "$ABL/run_row_b.sh"
bash "$ABL/run_row_c.sh"
```

每个测点、每次启动结束时，日志里都会打印 `[point] … elapsed_s=…` 和 `[launch] … elapsed_s=…`。

每次启动的输出：
- `$ROOT/<row>/…/result.jsonl`
- `launch.json`
- `run.log`
- `gpu_before.txt`、`gpu_after.txt`（别人进程的快照）
