## 2. 对比方法（6 条，含本方法）

固定 TP2、固定 TP4、Llumnix（两套权重常驻）、Flying（TP2 权重视图）、重启（35 s 重载 + 重新 prefill）、**WeaveTP**。
AnchorTP 不进本图（只做切换级对比）。所有方法用同一组请求、相同输入 / 输出 token 工作量、相同 GPU 与显存、完成相同任务；各方法按同一规则用自己的容量与约束离线生成自己的切换计划。

## 3. 负载构造（真实数据，可重复抽样）

### 长段（固定）
- 174 条**真实长请求**，从 Sky-T1 / OpenR1-Math / LIMO / s1K / LongWriter 池中取**总长（输入 + 输出）7.6k–8.4k（8k ±5%）、输入 ≤ 800** 的样本，不放回抽样（池中约 472 条可选）。
- 174 = 0.95 × TP4 全集群并发（184），高于 TP2 并发（152）→ 落在"TP2 两批、TP4 一批"的容量窗口内。

### 短段（主图横轴变量）
- **真实 prefill 为主请求**：ShareGPT 中**输入 ≥ 512、输出 ≤ 64** 的子集（9,810 条，平均输入 724 / 输出 21），有放回重复使用。
- 条数 = 横轴值 × 174，分布在长段前后各一半。

### 到达方式
- 连续提交（FCFS 严格接纳，不跳队首），按回放输出长度预留 KV。

## 4. 切换计划（预先分配，非自主）

- 第 1 条长请求接纳前：2 → 4。
- 最后一条长请求完成后：4 → 2。
- 共 **2 次切换**。缩容规则在 throttle 与 after_long 中取较好者。

## 6. 正式实验前必须说明或校准的三个前提

1. **容量窗口**：长段条数须落在 TP2 并发与 TP4 并发之间（§28 批次边界效应，窗口外对 TP2 回落到约 1.0）。报告时说明长段条数取法。
2. **TP4 prefill 慢于 TP2**：实测 PREFILL 为 TP2 9,790 / TP4 5,341 tok/s/副本，且 TP4 副本数减半 → 集群 prefill 吞吐约为 TP2 的 1/2.7。这是本引擎（无 flash-attn、PCIe）特性；所有 baseline 同引擎，可如实解释。此特性是对固定 TP4 优势随短请求占比上升的根因。
3. **单步时间是否随上下文变化**：当前模拟假设不变，须用服务器"完整切换周期 + 上下文扫描"实测校准（命令 1 / 2）后再定稿数值。

## 8. 为什么只对比 TP2 ↔ TP4

在 16 × 32 GB PCIe GPU 上，DeepSeek-V2-Lite 的可行布局为 TP2×DP8（能放下模型的最小 TP）与 TP4×DP4（长上下文布局）。TP1 每卡权重约 17.7 GB（待实测），KV 仅剩约 12 GB、单副本不足 45k token，无法承担长段；当前实现为 TP×EP=2 固定配对，TP1×EP2×DP16 未验证。固定 TP2 / 固定 TP4 即这两个布局的静态版本，与 Gyges（TP1↔TP4）、Flying Serving（DP↔TP）、Shift（TP↔SP）只比"硬件上可行的一对布局"的做法一致。可选：附录补测 TP1 单副本 KV 容量与短请求吞吐。详见《进度总览》§35。

## 9. 对容错行（第 2 行 fail-slow、第 3 行 fail-stop）的约束（2026-10-14）

由第 1 行模拟得出，详见《进度总览》§36。

| 项 | 值 |
|---|---|
| 降级单元 | 节点实例（TP4×EP2，8 卡）：坏 1 卡 → 该节点 7 卡中选 4 卡重建 TP2×EP2，另一节点保持 TP4；全局接纳控制器按容量比例分请求 |
| 每次故障 | 两次选源事件：降级（dense 分片机内取、专家分片跨机取）+ 修复后扩回 |
| 注入 | 外部 injector，请求事件锚点离线排好，不做检测；注入时刻选在每卡 KV 未到峰值处，KV_used 作报告项 |
| 单次运行时长 | **5–7 min**（切换时间 12 s 对 35 s 只有在此量级才能在端到端显示；小时级窗口只剩 1.01–1.08） |
| 修复 / 扩回间隔 | 约 60–90 s（按窗口比例，替代原 5 min） |
| 横轴 | 窗口内故障（慢卡）事件次数 1 / 2 / 3 / 4，每次换一张卡 |
| 纵轴 | 端到端吞吐（归一化到无故障 TP4）；辅图逐事件 TFS、TTP、总时长 / overhead（AnchorTP 论文口径） |
| 基线 | 重启（显存全给 KV，故障时驱逐 + 重新 prefill）、AnchorTP 代理（需补 CMM 主机重载）、可选 SP 不恢复；fail-slow 另加"不处理" |
| fail-slow | 只做计算型；慢卡状态可读、作为候选源，选源应避开它 |
